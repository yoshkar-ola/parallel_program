# Лабораторная работа № 1. Работа с потоками

## Сборка и запуск

```console
cmake -S . -B build
cmake --build build
.(твой путь укажи)/LW1 5

(обычно после сборки он так выглядит) 
.\build\Debug\LW1.exe 5
```

Для многоконфигурационного генератора путь к программе может содержать каталог
конфигурации, например `build/LW1/Debug/LW1.exe`.

## Ответы на вопросы

1. **Почему порядок строк при каждом запуске разный?**
   Потоки работают одновременно, и программа заранее не знает, какой из них получит процессорное время первым. Это решает планировщик операционной системы,
   поэтому порядок сообщений может меняться при каждом запуске.

2. **Чем `std::jthread` отличается от `std::thread`?**
   `std::jthread` при уничтожении сам дожидается завершения потока. При работе со `std::thread` обычно нужно вручную вызвать `join()`.
   Если этого не сделать и
   объект потока всё ещё будет активен, программа завершится через `std::terminate()`.

3. **Что будет, если передавать номер потока по ссылке?**
   Все потоки будут обращаться к одной переменной `i`, которая продолжает изменяться в цикле. Из-за этого номера могут оказаться неправильными, а также
   возникнет гонка данных. Поэтому в программе номер передаётся по значению: `threads.emplace_back(Worker, i)`.

4. **Почему вывод может перемешиваться?**
   Несколько потоков могут одновременно писать в `std::cout`, поэтому части разных сообщений иногда смешиваются. Для вывода используется `std::osyncstream`: он       сначала собирает всю строку, а потом выводит её целиком.

5. **Что произойдёт при `N = 10 000`?**
   Программа просто отработает с 10 000 потоками, при тестировании я не заметил каких-то изменений, возможно то, что она отработала немгновенно. Как вариант из за    того что создание потоков требует системных ресурсов, в случае если поток будет невероятно большим скорее всего вылетит ошибка по типу `std::system_error`.
