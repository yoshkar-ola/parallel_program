# Лабораторная работа № 1. Работа с потоками

## Сборка и запуск

```console
cmake -S . -B build
cmake --build build
.(твой путь укажи)/LW1 5

(обычно после сборки он так выглядит) 
.\build\Debug\LW1.exe 5
```

Для многоконфигурационного генератора путь к программе может содержать каталог
конфигурации, например `build/LW1/Debug/LW1.exe`.

## Ответы на вопросы

1. **Почему порядок строк при каждом запуске разный?** Потоки выполняются
   конкурентно, а порядок получения ими процессорного времени определяет
   планировщик операционной системы. Программа не задаёт порядок вывода.

2. **Чем `std::jthread` отличается от `std::thread`?** Деструктор `jthread`
   запрашивает остановку и выполняет `join()`. Для `thread` ожидание нужно
   организовать вручную: уничтожение присоединяемого (`joinable`) объекта
   `std::thread` вызывает `std::terminate()`.

3. **Что случится при передаче номера по ссылке?** Все потоки могут читать одну
   и ту же изменяемую переменную цикла. Возникает гонка данных, номера становятся
   неверными, а поведение программы — неопределённым. В программе номер передаётся
   по значению: `threads.emplace_back(Worker, i)`.

4. **Почему вывод мог «рваться»?** Несколько потоков одновременно выполняют
   отдельные операции записи в общий `std::cout`. `std::osyncstream` накапливает
   строку в собственном буфере и целиком передаёт её в `cout` при разрушении,
   поэтому символы разных строк не перемешиваются.

5. **Что произойдёт при `N = 10 000`?** Создание потока требует системных
   ресурсов, прежде всего памяти под стек и служебные структуры ядра. Лимит может
   быть исчерпан раньше создания 10 000 потоков, и конструктор выбросит
   `std::system_error`. Уже созданные `jthread` корректно завершатся при разрушении
   вектора, а программа выведет ошибку и вернёт ненулевой код. Если ресурсов
   достаточно, программа отработает, но с большими накладными расходами; для
   реальной массовой обработки обычно применяют пул потоков.
